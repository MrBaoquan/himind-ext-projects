# AndX 定制页交付

管理员授权开发者 → 后台复制接入信息 → 粘贴到支持安全导入的 HiMind 对话 → 选择并绑定工程的 AndX 展项 → 开发与真实 SDK 测试 → 上传候选隔离预览 → 一次精确发布确认 → 固定二维码与微信验收。

无需在 HiMind 侧填写 Profile，也无需为页面预先注册设备。多项目或多展项只在绑定时选择一次，后续工具从当前工程绑定读取凭证引用和明确目标。

`workflow.json` 是执行契约，`ui/workflow-view.json` 是声明式 UI。候选路径和 SHA 来自打包步骤，部署编号及线上修订来自预览步骤，不能手工抄写或在激活前静默刷新。并发冲突后重新展示目标与候选供确认。

Bridge 夹具验证 SDK 协议，不证明页面业务 UI 或现场硬件。候选预览会停用支付、内容提交和现场动作；生产激活后再检查固定 `/x/` 与微信双入口。设备接入是另一个授权动作。

默认出口为 preview_ready，只上传隔离预览。要发布时显式选择 activated 或 delivered 出口，经过精确制品确认；不提供名称误导的“只预览”入口。每种来源均先解析工程绑定，MyriadBox 先开发再构建，静态目录由构建回执和入口字段解析，后续打包沿用检查回执。

最低 Agent 0.3.94。只有一个开发入口，构建来源字段选择静态 H5 或 MyriadBox，默认出口 preview_ready。发布说明默认“确认发布当前已验证候选”。运行时业务报告保留原 Schema，单独登记文件化制品；候选、Bridge、部署和清单由工具登记，执行器逐份验证摘要、字节数与 Schema。
