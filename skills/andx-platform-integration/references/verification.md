# 验收与报告

> 状态：active ｜ 最后更新：2026-11-24 ｜ 负责人：AndX 维护者

每个“宿主＋目标＋能力”分别记录，不给整个平台一个笼统支持标签：

| 层级 | 证明范围 | 不能推出 |
| --- | --- | --- |
| 设计依据 | 架构允许路径 | 已实现/发布 |
| 实现检查 | 版本含 API/适配代码 | 运行正确 |
| 契约/本地测试 | 当前源码符合 fixtures/类型/模拟场景 | 真实鉴权/网络/设备通过 |
| 真实服务 | 指定环境链路往返 | 未测设备或物理履约通过 |
| 目标设备 | 指定构建/设备完成观察 | 其他 ABI/版本自动通过 |

每项用 passed、failed、pending、not_applicable，并附证据/理由；失败不改为待验，不适用不隐藏请求内缺口。

## 校验选择

先读实际 package.json。契约源码在手时，于 andx-sdk-spec 运行适用的 `npm run validate:exhibit-interaction` 或 `npm run validate:interaction-bridge`。没有脚本的消费工程不盲跑。

改 Web SDK 源码运行其 typecheck/test/build；消费 SDK 运行消费工程相关测试/构建。Unity 用对应引擎的相关 EditMode/PlayMode 与目标构建。构建写文件时遵守租约，保护已有产物。

按能力选场景：

- 分享/收图：创建、完成、取消、过期、下载失败、二维码可达、退出释放。
- 身份：会话失效、CSRF/来源、未授权节点/展项；跨租户拒绝由服务端测试证明，UI 参数检查不代替授权。
- 控制/履约：未知/未声明动作、过期/重复、取消/超时、断线恢复、安全停止；接收 ACK 与真实 PLAYING 分开。
- 媒体：来源、路径穿越、大小/类型/哈希失败与清理，分块/续传只在本次使用时验证。
- 设备：启动、权限/桥接、暂停/退出、重连与本地安全，现场硬件保留观察结果。

SDK 单测、模拟服务、真实接口与设备证据分别标记。真实支付、退款、计费 AI 和硬件动作须有本任务明确授权，普通冒烟使用受控夹具。
