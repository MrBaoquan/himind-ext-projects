# AndX 跨平台接入助手

为已有工程选择 AndX 接入路径、完成最小适配并按证据验收。仅开发普通 UI、发布 UPM 包或交付定制页时使用相应技能，本技能只补充 AndX 接入决策。

## 先识别工程与事实源

1. 读取目标仓库指令、工作区现状、依赖锁文件和构建目标，确认用户所需能力。不要从操作系统推断宿主，不假设已安装 UNIHper、IODevice 或 MyriadBox。
2. 使用可用的 HiMind 工程上下文解析能力；缺工程清单时检查用户指定工程的实际文件。缺业务 ID 或部署环境只阻断依赖它的联调，不阻断本地检查。业务稳定 ID 通过 Workbench Provider 解析，展示编号不能代替路由 ID。
3. 修改前取得 HiMind 工作区写租约，保留其他改动。记录 SDK/宿主版本、lock/ref/commit 和 dirty 状态；HEAD 不能代表未提交源码的完整指纹。
4. 按 [平台选择](references/platform-selection.md) 建立“宿主×目标×能力×部署方式”矩阵，只加载命中的参考。
5. 协议以匹配版本的 `andx-sdk-spec` 为事实源，调用以该版本 SDK 类型为依据。没有源码仓时使用版本化契约、安装包文档与类型；无法获得契约则列缺口，不猜字段、不重写签名。

## 开发身份与现场身份

- 多展项页面开发使用开发者个人密钥，权限授予项目或展项集合；后台复制接入 JSON 后交给支持安全导入的 HiMind 对话，本机自动保管，不要求手工配置。
- 页面交付读取工程绑定；工作台 pid 与 AndX 编号是不同身份，必须通过授权目录确认。开发页面和新建展项都不需要预先注册设备。
- 现场设备使用一次性接入码首次注册，可信宿主保存独立运行密钥；开发者密钥不进入设备、网页、WebGL、静态候选包或截图。
- Unity/UNIHper 使用异步自动初始化并等待就绪；Windows 默认 DPAPI。已有设备凭证启动时复用，不重复消费接入码。其它宿主先核实 SDK 的注册/安全存储实现，不将支持声明当作实测。

## 按运行环境路由

| 场景 | 读取与复用 |
| --- | --- |
| Unity，独立或 UNIHper | [Unity](references/unity.md)；UNIHper 工程配合 `unihper-unity-development` |
| 普通 H5、公开 token 页、MyriadBox | [Web/MyriadBox](references/web-myriadbox.md)；宿主开发配合 `exhibit-web-development` |
| AndX sandbox iframe 定制页 | 转入 `andx-custom-page-development`，交接静态目录、版本和 Bridge 能力 |
| UE | [UE](references/unreal.md)，先查真实插件与回调缺口 |
| Unity WebGL | Unity 的 WebGL 小节与 Web 的凭据边界 |
| 多屏、多进程、非 IODevice 原生应用 | [Hub/NetIO](references/hub-netio.md) |

同伴技能或插件缺失时，先发现本机/市场能力并核对来源、版本、依赖。可继续独立检查和已授权本地适配，受依赖限制的操作列为待办；不自动安装，不声称未执行的测试已通过。仅增加 SDK 调用不要求重新走整套展项立项流程。

## 共用边界

- AIP 是外部业务语义，IOUI 是本地映射，Interaction Bridge 是定制页受限边界，三者不能互相替代。架构推荐不等于存量实现；不强制把可用 SDK 迁移到尚未验证的链路。
- 复用 SDK/Provider 和契约，不复制字段、错误码、签名或状态机。旧示例与契约冲突时记录差异；原始 IO 代理等安全冲突阻断受影响链路，不能照抄上线。
- 浏览器、WebGL、静态包和证据不含 NodeSecret、bootstrap key、支付或 AI 厂商密钥；原生长期凭据由可信宿主与部署设施保管，不随源码/公共制品分发。只记录配置来源和存在性，不回显值。
- 租户、节点与展项授权由服务端决定，客户端 exhibitId 和展示编号不替代授权，业务访问保留 tenant_id 隔离。
- 远程动作使用已声明语义能力，不代理任意原始 IO；物理设备由单 Host 持有。媒体字节走内容面，控制面只传受限引用。
- 支付与物理履约分别验收，金额用整数分；客户端支付回调不直接启动设备。普通冒烟不自动消费真实支付、计费 AI 或触发硬件。

## 实施循环与完成条件

先记录路径、版本、身份责任方和缺口，复用用户已有部署选择。选一条已请求的最小链路，例如收图会话→出码→上传完成→展示；只增加必要配置与适配层。

按项目生命周期处理初始化、主线程回调、取消、订阅和释放。远程控制补齐 TTL/幂等、本地安全停止与真实运行确认。按 [验收](references/verification.md) 跑相关契约、测试、构建和异常场景，缺目标设备时保留待验。

更新项目既有接入说明和脱敏证据；可用时生成开发检查点，完成后释放租约。生产激活、公开分发与上传按用户授权和所用交付流程执行。

输出：路径依据、修改文件、版本与源码状态、命令结果、证据和待验项。对每个平台＋能力分别报告设计依据、实现存在性、契约测试、真实服务联调、目标设备实测，各项使用通过/失败/待验/不适用并附理由。编译成功不等于真机通过，历史报告不等于当前复验，平台声明不等于全部能力支持。

## 当前接入版本

本流程最低 HiMind Agent 0.3.94、AndX 定制页工具 0.2.0。授权展项目录按 `nextCursor` 继续查询，向目录能力传入 `after_id`，不要把第一页当作全部展项。原生 AI 页面在粘贴阶段本机导入，随后按当前任务工程明确绑定；不使用共享全局展项。

后台复制 JSON 保留通用 `importProtocol: "himind.credential-import.v1"` 与 `extensionId`。工作台只做通用信封预分类，普通云端聊天不依赖本机安全导入；命中信封且本机不可用或验证失败时禁止保存/发送原文。秘密由本机通用设施保管，AndX 身份/目录/目标/发布由扩展与服务端解释；工作台账号认证及本机操作票据与 AndX 开发密钥相互独立。仅支持声明可识别的入口，不保证任意自由文本、编码、附件或外部客户端历史。
