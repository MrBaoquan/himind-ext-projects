# 展项体验验收

## 自动检查

### 文案

- 搜索禁用词：`开启一段`、`奇妙旅程`、`无限可能`、`未来已来`、`科技与艺术`、`赋能`、`重新定义`。
- 扫描主操作按钮，必须包含动词和对象；不得只有 `GO`、`START`、`CONTINUE`。
- 扫描错误文案，必须包含原因、内容状态和下一步中的至少两项。
- 主题句每屏不超过一句；装饰性英文 Slogan 为 0。
- 同一业务流程中的按钮名称一致。

### 状态与转场

- 页面状态机至少覆盖 `idle`、`active`、`processing`、`success`、`error`；有网络或设备能力时再覆盖 `offline`。
- 代码不得以 `transitionend` 或 `animationend` 推进订单、上传、页面完成或业务状态。
- 连续触发主操作 20 次，不出现重复提交、卡死、空白页或计时器累加。
- 错误与离线状态不需要等待转场。
- 页面隐藏时停止轮询、音频和高成本动画。

### 动态与可访问性

- 每屏至少两类动态：环境、状态、交互反馈。
- 所有主要交互有 80–140ms 内的可见响应。
- `prefers-reduced-motion` 下停止位移、旋转、视差和环境循环。
- 触摸目标建议不小于 44×44 CSS px，主操作建议更大。
- 文字与背景在目标屏幕上可读，环境动画不降低关键文字对比度。

### 性能

- Console 零未处理错误。
- 网络面板无非预期 4xx/5xx；离线态属于预期时必须在证据中标记。
- 本地首屏内容目标 2.5 秒内可见，主要操作 4 秒内可用。
- 初始 JS/CSS（不含媒体）建议不超过 3MB gzip。
- 转场中无超过 200ms 的主线程长任务。
- 连续运行 10 分钟，内存、计时器、音频实例和 Provider 轮询不持续增长。
- 主流设备目标 60fps；低端 Android WebView 不因装饰动画失去可操作性。

## 证据清单

至少保存：

1. 目标分辨率截图：首屏、输入、处理中、成功、错误、离线。
2. 20 次连续主要操作记录：成功次数、卡死次数、重复提交次数。
3. Console 截图或结构化摘要：错误数、警告数。
4. 网络摘要：失败请求、超时、预期离线请求。
5. reduced-motion 截图或录屏。
6. 目标设备性能记录：帧率、长任务、内存趋势。
7. Provider 状态：Mock 或真实，禁止混淆。
8. 人工确认：触摸、声音、视频、实体输入与安全停止。

建议证据 JSON：

```json
{
  "copy": { "forbiddenHits": 0, "themeLinesPerScreen": 1 },
  "transition": { "runs": 20, "stuck": 0, "duplicateSubmits": 0 },
  "runtime": { "consoleErrors": 0, "unexpectedNetworkFailures": 0 },
  "motion": { "categories": ["environment", "status"], "reducedMotion": true },
  "providerMode": "mock",
  "manual": { "touch": "pending", "sound": "pending", "realDevice": "pending" }
}
```

## 人工验收

以下项目不能由自动截图代替：

- 触摸手感与命中区域。
- 音量和现场噪声下的可听性。
- 视频起播、切换和循环是否黑屏。
- 实体按钮、Modbus、动感平台等 Provider 行为。
- 安全停止、断网恢复和工作人员处置路径。
- 目标设备上的 reduced-motion 与长时间稳定性。

## 完成判定

只有自动检查、截图/日志、目标设备回归和人工项目全部有证据时才判定体验完成。任何一项缺失都必须明确列出，不用“整体效果良好”代替。
